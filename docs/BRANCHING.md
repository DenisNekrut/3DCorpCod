# Правила ветвления и слияния

Основная ветка: `main`.

## Имена веток
- `feature/00-architecture`
- `feature/01-workspace-ui`
- `feature/02-objects-transforms`
- `feature/03-ruler-precision`
- `feature/04-boolean-geometry`
- `feature/05-advanced-geometry`
- `feature/06-projects-storage`
- `feature/07-import-export-print`
- `feature/08-ci-testing-release`

## Правила
- Не вести разработку напрямую в main.
- Каждая задача имеет GitHub Issue.
- Каждая ветка решает ограниченный набор задач.
- Перед слиянием открыть Pull Request в main.
- PR должен содержать ссылку на Issue, описание изменений и результаты проверки.
- Обязательны успешная сборка и тесты.
- Не объединять архитектурно несовместимые изменения без предварительного согласования.
- Коммиты должны иметь понятные сообщения.

## Порядок интеграции
Архитектура → рабочая область → объекты и линейка → булева геометрия → расширенная геометрия → проекты и хранение → импорт/экспорт → релизная проверка. CI настраивается параллельно.
