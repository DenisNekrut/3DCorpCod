## 1. Результат аудита

Проект уже имеет рабочую технологическую основу. Переписывать его с нуля не требуется. Сохраняем текущий стек и постепенно отделяем доменную модель, вычисление геометрии, представление сцены, хранение и экспорт.

| Область | Фактическая технология |
|---|---|
| UI | React 19, TypeScript |
| Сборка | Vite 6 |
| 3D | Three.js 0.179, React Three Fiber 9, Drei 10 |
| Состояние | Zustand 5 |
| Булева геометрия | three-bvh-csg 0.0.17 |
| Локальное хранение | IndexedDB; localStorage для недавних проектов и библиотеки |
| Экспорт | STLExporter, 3MF через fflate, OBJ |
| Тестирование | Vitest 3; существующие тесты геометрии найдены в src/geometry/createObjectGeometry.test.ts |

### Уже существующие сильные стороны

- Разделены каталоги app, components, editor, geometry, storage и export.
- Есть единая модель ModelObject и документ ProjectDocument.
- createObjectGeometry используется для построения геометрии.
- Булевы результаты вычисляются из исходных объектов, сохраняя параметрическую структуру.
- Локальный origin геометрии центрируется, позиция и вращение задаются отдельно.
- Существуют тесты импортированной сетки, фасок/скруглений, габаритов и якорей примитивов.

## 2. Архитектурные риски

1. **App.tsx перегружен ответственностями.** Верхний компонент совмещает экраны проектов, импорт/экспорт, автосохранение, библиотеку пресетов и UI-состояния.
2. **Общий экземпляр Evaluator.** createBooleanGeometry использует один экземпляр three-bvh-csg Evaluator. Нужно проверить перекрывающиеся вычисления и владение ресурсами.
3. **Преобразования не сведены к единому контракту.** Viewport, preview и экспорт применяют трансформации в отдельных местах.
4. **Нет слоя миграций схемы.** ProjectDocument имеет schemaVersion 1, но validate → migrate → normalize не выделен.
5. **Хранение ориентировано на current-project.** IndexedDB имеет object store projects, однако saveProject/loadProject используют фиксированный ключ; каталог проектов нуждается в отдельном repository.
6. **Вычисление геометрии вызывается напрямую из UI и экспортёров.** Нужна единая точка оценки геометрии и управления ресурсами.
7. **Проверка печатаемости эвристическая.** AABB-проверки не являются полноценной диагностикой manifold-сетки.
8. **Тесты есть, но их прохождение не подтверждено.** В репозитории найден createObjectGeometry.test.ts; запуск в чистом окружении пока не выполнен.
9. **Нет package-lock.json.** Сейчас нельзя использовать npm ci и гарантировать идентичную установку транзитивных версий. Добавить lock-файл и перейти на npm ci — обязательная задача перед стабильным CI.

## 3. Целевая архитектура

Сохраняем React + TypeScript + Three.js + React Three Fiber + Zustand. Не переписываем проект и не добавляем новый CAD kernel без сравнительных испытаний.

```text
src/
  app/                    # композиция приложения и экраны
  features/
    workspace/            # рабочая область, панели и toolbar
    projects/             # список, создание, переименование, удаление
    object-library/       # примитивы и пользовательские пресеты
    properties/           # редактирование параметров
    import-export/        # сценарии импорта/экспорта
  domain/
    project/              # ProjectDocument, schema, migrations, validation
    scene/                # ModelObject, координаты и единицы
    commands/              # команды редактора, Undo/Redo
  state/
    editorStore.ts
  geometry/
    primitives/           # построение базовых фигур
    operations/            # union / subtract / intersect
    modifiers/             # фаски и скругления
    evaluation/            # единая точка вычисления геометрии
    validation/            # bounds и диагностика сеток
  viewport/
    components/            # R3F-сцена и манипуляторы
    adapters/              # доменная модель <-> Three.js
  infrastructure/
    persistence/           # IndexedDB repositories и автосохранение
    file-formats/          # STL / 3MF / OBJ
    workers/                # будущие Web Workers после профилирования
  shared/
    units/
    errors/
    utils/
```

Это целевая структура, не требование немедленно переместить все файлы. Миграция выполняется небольшими PR.

## 4. Контракты подсистем

### 4.1 Доменная модель

- Координаты и размеры документа — миллиметры.
- Локальная геометрия центрирована относительно origin.
- position задаёт положение origin в мировых координатах.
- rotation хранится в градусах; перевод в радианы — на границе Three.js.
- dimensions — положительные габариты; UI допускает шаг 0,1 мм без округления внутренних вычислений.
- Загрузка проходит validate → migrate → normalize.

### 4.2 Геометрическое ядро

Ядро должно быть независимо от React и Zustand:

```ts
type BooleanOperation = 'union' | 'subtract' | 'intersect';

interface GeometryEvaluationInput {
  document: ProjectDocument;
  targetObjectId: string;
}

interface GeometryEvaluationResult {
  geometry: BufferGeometry;
  bounds: { min: [number, number, number]; max: [number, number, number] };
  warnings: GeometryWarning[];
}

interface GeometryKernel {
  createPrimitive(object: ModelObject): BufferGeometry;
  evaluate(input: GeometryEvaluationInput): GeometryEvaluationResult;
  validate(geometry: BufferGeometry): GeometryValidationResult;
}
```

Правила: операции не мутируют документ; ошибки типизированы; владение BufferGeometry явно; каждый ресурс освобождается ровно один раз. Общий Evaluator не используется параллельно без подтверждения тестами.

### 4.3 Viewport

Viewport — представление доменной модели, не источник истины. Во время drag допустимо временное состояние, по завершении жеста результат фиксируется одной командой. Снятие выделения не должно менять параметры объекта.

### 4.4 Хранение

```ts
interface ProjectRepository {
  list(): Promise<ProjectSummary[]>;
  get(id: string): Promise<ProjectDocument | null>;
  save(project: ProjectDocument): Promise<void>;
  delete(id: string): Promise<void>;
}
```

IndexedDB — основное хранилище проектов; localStorage — только настройки и небольшие некритичные данные. Автосохранение привязано к ID проекта.

### 4.5 Экспорт

Экспортёр получает неизменяемый снимок документа и итоговую геометрию через GeometryKernel. STL и 3MF используют одинаковую оценённую геометрию и систему координат.

## 5. Технологические решения

| Задача | Решение |
|---|---|
| UI | Оставить React + TypeScript |
| 3D | Оставить Three.js + R3F + Drei |
| State | Оставить Zustand |
| Булевы операции | Пока оставить three-bvh-csg за адаптером; сначала испытать устойчивость |
| Persistence | IndexedDB через repository |
| Тяжёлые операции | Worker после профилирования |
| Тесты | Vitest; добавить отдельные тесты CSG, store и экспорта |

Испытать булевы операции на корпусах, отверстиях, касаниях, копланарных гранях, тонких стенках и последовательных операциях. Только после этого решать, требуется ли другое ядро.
