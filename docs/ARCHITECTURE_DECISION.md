# 3DCorpCod — архитектурное решение (ADR-0001)

**Статус:** предложено к утверждению  
**Дата анализа:** 31.10.2026  
**Связанная задача:** [#5 — Архитектура и геометрическое ядро](https://github.com/DenisNekrut/3DCorpCod/issues/5)

## 1. Результат аудита

Проект уже имеет рабочую технологическую основу. Переписывать его с нуля не требуется. Рекомендуется сохранить текущий стек и постепенно отделить доменную модель, вычисление геометрии, представление сцены, хранение и экспорт.

| Область | Фактическая технология |
|---|---|
| UI | React 19, TypeScript |
| Сборка | Vite 6 |
| 3D | Three.js 0.179, React Three Fiber 9, Drei 10 |
| Состояние | Zustand 5 |
| Булева геометрия | three-bvh-csg 0.0.17 |
| Локальное хранение | IndexedDB; localStorage для недавних проектов и библиотеки |
| Экспорт | STLExporter, собственный 3MF через fflate, OBJ |
| Тестирование | Vitest 3 (скрипт test объявлен) |

Источник: 3DCorpCod/package.json и исходные модули репозитория.

### Что уже хорошо устроено

- Есть отдельные каталоги app, components, editor, geometry, storage и export.
- Есть единая модель ModelObject и документ ProjectDocument.
- Примитивы строятся общей функцией createObjectGeometry, используемой viewport и экспортом.
- Булевы результаты вычисляются из исходных объектов, а не только хранятся как необратимый меш.
- Локальный origin геометрии центрирован; позиция и вращение задаются отдельно.
- Размеры и координаты задуманы в миллиметрах.

## 2. Архитектурные проблемы и риски

1. **App.tsx перегружен ответственностями.** Верхний компонент одновременно управляет экраном проектов, импортом, экспортом, автосохранением, библиотекой пресетов и UI-состояниями. Это усложняет тестирование и повышает риск регрессий.
2. **Общий экземпляр Evaluator.** В createBooleanGeometry используется один экземпляр three-bvh-csg Evaluator. Нужно проверить поведение при перекрывающихся вычислениях и явно определить владение ресурсами.
3. **Нет единого контракта преобразований.** Viewport, preview и экспорт самостоятельно применяют позицию/вращение. Это может привести к различиям в координатах.
4. **Нет миграций схемы проекта.** ProjectDocument имеет schemaVersion 1, но отдельного слоя validate → migrate → normalize пока не видно.
5. **Хранение пока ориентировано на один текущий проект.** IndexedDB имеет object store projects, но saveProject/loadProject используют фиксированный ключ current-project. Каталог нескольких проектов нужно выделить отдельно.
6. **Геометрия вызывается напрямую из UI и экспортёров.** Нужна единая точка вычисления итоговой геометрии, ошибок и освобождения ресурсов.
7. **Проверка печатаемости эвристическая.** Текущая проверка размеров и пересечения AABB не является полноценной проверкой manifold-сетки.
8. **Результаты сборки и тестов не подтверждены этим аудитом.** Наличие Vitest в package.json не доказывает, что тесты проходят.

## 3. Целевая архитектура

Сохраняем React + TypeScript + Three.js + React Three Fiber + Zustand. Не переписываем проект и не добавляем новый CAD kernel без сравнительных испытаний.

Предлагаемое дерево:

```text
src/
  app/                    # композиция приложения и экраны
  features/
    workspace/            # рабочая область, панели и toolbar
    projects/             # список, создание, переименование, удаление
    object-library/       # примитивы и пользовательские пресеты
    properties/           # редактирование параметров
    import-export/        # пользовательские сценарии файлов
  domain/
    project/              # ProjectDocument, schema, migrations, validation
    scene/                 # ModelObject, координаты и единицы
    commands/              # команды редактора, Undo/Redo
  state/
    editorStore.ts         # состояние интерфейса и вызов доменных команд
  geometry/
    primitives/            # построение базовых фигур
    operations/            # union / subtract / intersect
    modifiers/             # фаски, скругления и будущие модификаторы
    evaluation/            # единая точка вычисления геометрии
    validation/            # bounds и диагностика сеток
  viewport/
    components/             # R3F-сцена и манипуляторы
    adapters/               # доменная модель <-> Three.js
  infrastructure/
    persistence/            # IndexedDB repositories и автосохранение
    file-formats/           # STL / 3MF / OBJ
    workers/                # будущие Web Workers после профилирования
  shared/
    units/                  # миллиметры и преобразования
    errors/                 # типизированные ошибки
    utils/
```

Это целевая структура, а не требование немедленно переместить все файлы. Миграция должна идти небольшими PR без массового переименования.

## 4. Контракты подсистем

### 4.1 Доменная модель

- Все размеры и координаты документа — в миллиметрах.
- Локальная геометрия объекта центрирована относительно собственного origin.
- position задаёт положение origin в мировых координатах.
- rotation хранится в градусах; перевод в радианы выполняется на границе Three.js.
- dimensions — положительные габариты локальной геометрии; минимальное значение UI — 0,1 мм.
- Шаг интерфейса 0,1 мм не должен округлять промежуточные вычисления ядра.
- Загрузка проекта проходит через validate → migrate → normalize.

### 4.2 Геометрическое ядро

Публичный контракт ядра должен быть независим от React и Zustand:

```ts
type BooleanOperation = 'union' | 'subtract' | 'intersect';

interface GeometryEvaluationInput {
  document: ProjectDocument;
  targetObjectId: string;
}

interface GeometryEvaluationResult {
  geometry: BufferGeometry;
  bounds: { min: [number, number, number]; max: [number, number, number] };
  warnings: GeometryWarning[];
}

interface GeometryKernel {
  createPrimitive(object: ModelObject): BufferGeometry;
  evaluate(input: GeometryEvaluationInput): GeometryEvaluationResult;
  validate(geometry: BufferGeometry): GeometryValidationResult;
}
```

Правила:
- Операции не мутируют исходный документ.
- Ошибка возвращается как типизированная ошибка; исходные объекты остаются доступными.
- Результирующая геометрия принадлежит вызывающей стороне и должна освобождаться через dispose.
- Для геометрии должен быть понятен владелец; нельзя допускать двойной dispose.
- Общий evaluator не используется одновременно в нескольких задачах, пока это не подтверждено тестами.

### 4.3 Viewport

Viewport отображает доменные объекты, но не является источником истины. Во время drag допустимо временное интерактивное состояние, однако по завершении жеста результат фиксируется одной командой в состоянии редактора. Снятие выделения не должно менять параметры объекта.

### 4.4 Хранение

Ввести интерфейс репозитория:

```ts
interface ProjectRepository {
  list(): Promise<ProjectSummary[]>;
  get(id: string): Promise<ProjectDocument | null>;
  save(project: ProjectDocument): Promise<void>;
  delete(id: string): Promise<void>;
}
```

IndexedDB — основное хранилище проектов. localStorage допустим для небольших настроек и некритичных кэшей. Автосохранение должно быть привязано к ID проекта и поддерживать восстановление.

### 4.5 Экспорт

Экспортёр принимает неизменяемый снимок документа и получает итоговую геометрию через GeometryKernel. STL и 3MF должны использовать одинаковую оценённую геометрию и систему координат. Единицы и масштаб проверяются тестами на контрольных моделях.

## 5. Решения по технологиям

| Задача | Решение | Обоснование |
|---|---|---|
| UI | Оставить React + TypeScript | Уже используется |
| 3D | Оставить Three.js + R3F + Drei | Текущая сцена построена на них |
| State | Оставить Zustand | Есть store и история |
| Булевы операции | Пока оставить three-bvh-csg за адаптером | Сначала измерить точность и устойчивость |
| Persistence | IndexedDB через repository | Подходит для локальных документов |
| Тяжёлые операции | Подготовить Worker-интерфейс; внедрять после профилирования | Не усложнять преждевременно |
| Тесты | Vitest + тесты геометрии и сериализации | Vitest уже в зависимостях |

До замены three-bvh-csg провести испытания на корпусах, отверстиях, касаниях, копланарных гранях, тонких стенках и цепочках операций. Если устойчивость недостаточна, отдельно сравнить альтернативные ядра и лицензии.

## 7. Критерии завершения

- Архитектурное решение утверждено и хранится в репозитории.
- Сборка и тесты воспроизводимо запускаются.
- Геометрическое ядро покрыто тестами основных операций.
- Viewport, preview и экспорт используют единый путь оценки геометрии.
- Загрузка проверяет версию и структуру документа.
- Изменения находятся в feature/00-architecture и предложены через Pull Request в main.

## 8. Лицензии

Проверка только по именам зависимостей не заменяет юридическую проверку конкретных версий и транзитивных пакетов. Перед релизом нужно сформировать полный список лицензий из lock-файла. Отдельно зафиксировать лицензии Three.js, React, Zustand, three-bvh-csg и fflate по опубликованным метаданным их фактических версий.
